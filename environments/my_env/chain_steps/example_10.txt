EXAMPLE 10  —  globally capped
========================================================================================

Deep configs deliberately cut short by max_global_depth, so every strand stops as soon as one reaches depth 2. Useful for short prompts from ambitious configs.

Provenance
----------------------------------------------------------------------------------------
  source          chain_examples.json, examples[9]
  generator       my_env.sequential_generate.gen_dependency_chains
  renderer        my_env.sequential_author.render_steps (deterministic, no LLM)
  seed_idx        31   (seed state = adapter.initial_state(Random(31)))
  global cap      2
  chain 0         max_depth=5  max_breadth=2  p_skip=0.0  p_cross=0.5  p_unrelated=0.0
  chain 1         max_depth=5  max_breadth=2  p_skip=0.0  p_cross=0.5  p_unrelated=0.0
  chain 2         max_depth=5  max_breadth=2  p_skip=0.0  p_cross=0.5  p_unrelated=0.0
  totals          2 turns, 6 actions (6 links + 0 distractors), depths [2, 2, 2]
  edges           3 total, 0 crossing threads, 0 object / 3 value, widest fan-in 1
  author slots    2 open-ended

Steps  (turn-major order; '<-' is a dependency, '=' a literal)
----------------------------------------------------------------------------------------

step 1  [read]  ask_question — Ask an AI-grounded question about a GitHub repository.
    repoName     ?  supplied by the author — GitHub repo in owner/repo form (or a list, max 10)
    question     ?  supplied by the author — the question to ask
    returns      free-text answer (nondeterministic)
step 2  [read]  read_wiki_structure — List the DeepWiki documentation topics for a GitHub repository.
    repoName     ?  supplied by the author — GitHub repo in owner/repo form
    returns      list of documentation topics
step 3  [read]  list_chats — List the chats the acting user is a member of.
step 4  [write]  reply_to — Reply to an existing message in its chat (threaded).
    message_id   =  m_038 (a message that already exists)
    text         <- must carry what step 1 returned
step 5  [write]  reply_to — Reply to an existing message in its chat (threaded).
    message_id   =  m_014 (a message that already exists)
    text         <- must carry what step 2 returned
step 6  [write]  send_message — Send a message from the acting user to a chat.
    chat_id      =  c_005 (a chat that already exists)
    text         <- must carry what step 3 returned

Thread membership  (the flat order above loses it; kept for later thread-major work)
----------------------------------------------------------------------------------------
  chain 0: steps 1, 4
  chain 1: steps 2, 5
  chain 2: steps 3, 6
  (* = distractor: depends on nothing and does not count toward depth)
