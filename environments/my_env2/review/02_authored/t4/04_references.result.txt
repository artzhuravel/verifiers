Stage 4. Each seed entity gets ONE way of being described instead of named.
The model picks only WHICH mode; the adapter derives the params from the world and
proves resolve(state, mode, params) == [that entity]. A mode that cannot be made to fit
is skipped and the next tried, so the stage is total — an entity with no working
reference raises, because v2 strips ids out and the task would be unanswerable.

  $message_0  ->  m_001
      the entity      in infra-team from Alice Morgan, unread by you: "Security flagged dependency 'belmont/cache' — can someone prepare a short repo summary (license, primary language, active maintainers/contact) and post it here by EOD?"
      mode chosen     message_by_text  (the model's pick)
      params derived  {"text": "Security flagged dependency 'belmont/cache"}
      reads as        "the message about Security flagged dependency 'belmont/cache"
      predicate       the one message whose text contains Security flagged dependency 'belmont/cache
      PROOF           resolve() -> ['m_001']   unique, and it is the target
